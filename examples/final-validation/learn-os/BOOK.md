Reader: a third-year computer science student who writes college-level C (loops, functions, a little about pointers), uses the terminal, has attended OS lectures and can recite the definitions, but has never watched the operating system do any of it; works on an Ubuntu laptop with gcc.
Promise: the reader can explain what the operating system really does when a program runs, makes processes and threads, is scheduled, shares data, uses memory and reads files, show each on their own Linux machine, and solve the standard exam problems (schedules, page replacement, deadlock, address translation) by hand.
Kind: system
Running project or case: one trace, `./hello` printing a line, followed at low resolution in chapter 1 and then zoomed into one stage per chapter (how the process is made in 2, how it gets the CPU in 3, how two threads share it in 4, where its bytes live in 5, how its output reaches a file in 6); from chapter 2 on, the reader's own tiny shell `ksh0` grows with each chapter's practice.
Pictures: the kernel as a guarded counter in an office that programs must ask at, never walk behind (breaks: the kernel also acts on its own, on interrupts); a process as a folder of papers the kernel keeps for each running program (breaks: threads share most of the folder); virtual memory as each process having its own private street numbering mapped to shared real houses (breaks: shared pages and copy-on-write).
Names: the reader's work folder is `~/os`; chapter programs live in `~/os/chNN/`; the running program is `hello.c`; the shell built from chapter 2 is `ksh0.c`.
Versions: Linux on x86-64, Ubuntu 24.04, gcc 13, glibc 2.39; output of strace and /proc shown as on that system; page size 4096 bytes.
Left at end of chapter 1: ~/os/ch01 holds the chapter's twelve programs (hello.c to copy.c) with builds and test files; the reader can strace a program and read its calls, descriptors, faults and signals; ksh0 starts in chapter 2.
